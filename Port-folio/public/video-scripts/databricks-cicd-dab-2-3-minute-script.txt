This project replaced manual Databricks deployment with a repeatable CI/CD path built around Databricks Asset Bundles and Azure DevOps. At Lindsay, notebooks and job configuration had been hand-copied between workspaces. That allowed code and configuration to drift, left no reliable review trail, and made it difficult to know exactly what was running in production.

I moved the deployment definition into version control. Databricks Asset Bundles described jobs, pipelines, cluster configuration, and environment settings in YAML. That meant a notebook change and the job definition that executed it traveled together instead of being updated independently inside a workspace.

Azure DevOps provided the validation and promotion workflow. Every pull request ran bundle validate, so broken bundle configuration could be caught before merge. After a change was accepted, the same bundle artifact moved through isolated development, test, and production workspaces. The artifact was promoted rather than rebuilt, which protected the environments from differences introduced during packaging.

Each environment had explicit behavior. Development auto-deployed after merge, used smaller clusters, and kept schedules paused. Test used a gated deployment, production-shaped data, and live schedules. Production required approval, ran with its exact schedule, and was owned through service-principal authentication rather than a personal token.

Environment-specific overrides let the same bundle express those differences without creating separate copies of the deployment definition. Development could remain inexpensive while production retained the settings required for its workload. Review checks, promotion gates, and service-principal ownership also made the release path visible and repeatable.

My contribution covered the Asset Bundle structure, YAML resource definitions, Azure DevOps validation, environment isolation, promotion strategy, overrides, approvals, and authentication model. The recorded outcome was three isolated environments—development, test, and production—and zero manual deployments. The solution is listed as in production. More importantly, code and infrastructure now follow one traceable release path. Instead of copying workspace objects and hoping environments match, the team can review one version-controlled change, validate it, and promote the same artifact through controlled gates to production. That removed workspace-level guesswork.
