This project created the core data foundation for operational reporting. The source information lived inside third-party systems that were reachable only through rate-limited APIs. There was no shared operational store, limited history beyond what each API exposed, and reporting queries risked repeatedly hitting the source systems directly.

I designed a two-tier architecture to separate source ingestion from analytics. The first tier was a SQL Server operational database. Ingestion jobs pulled data from the APIs and landed it there as the internal system of record. This gave the business a controlled copy of operational data and stopped dashboards from depending directly on external API availability and limits.

The second tier was the analytical warehouse. Azure Synapse dataflows read from the operational database and reshaped the data into a star schema. I designed fact tables for transactions, visits, and inventory events, with conformed dimensions for product, store, representative, and date. Because those dimensions were shared across subject areas, downstream reports could use consistent business entities instead of rebuilding their own definitions.

The loading pattern was incremental. Watermarks identified what had changed since the previous run, so dataflows did not need to reload the complete operational store. I also applied indexing and partitioning based on the dashboard query patterns documented for the project, supporting efficient refresh and analytical access as the warehouse grew.

Reliability was part of the pipeline rather than an afterthought. Every load included custom logging and failure notifications. Source-to-sink validation checked completeness for each run, and SQL test plans verified consistency across the operational and warehouse databases. Those controls helped distinguish a successful pipeline execution from a genuinely complete and consistent data load.

My contribution covered the API ingestion jobs, SQL Server operational model, Synapse transformation layer, dimensional warehouse design, incremental-loading logic, performance tuning, logging, notifications, and validation. The outcome was one governed foundation for downstream Power BI reporting: external APIs fed the operational layer, the operational layer fed a reusable star schema, and dashboards queried the warehouse instead of placing analytical demand on the source systems. No quantitative performance result is documented in the portfolio, so the demonstrated value is architectural—centralized history, consistent dimensions, controlled loading, and validated reporting data.
