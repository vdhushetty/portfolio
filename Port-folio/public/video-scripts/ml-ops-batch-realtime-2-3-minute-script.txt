A model can perform well in a notebook and still create no production value. The gap is operational: How is the approved model version deployed? How does the same prediction logic run in a schedule and behind an online endpoint? And when a prediction is questioned, can we identify which model produced it? This project addressed that gap by operationalizing machine-learning models for both batch and real-time inference. The original models did not have a repeatable path into scheduled workflows or low-latency applications. Building two unrelated deployment paths would create a second problem: different packaging, different versioning, and inconsistent traces. I created a shared lifecycle around MLflow. Training runs are tracked, approved models are registered and versioned, and promotion happens from that common registry. Inference is packaged consistently so the selected model can move into either serving path without losing its identity or feature contract. The first path is scheduled batch inference. It supports scoring workloads that run as jobs and produce predictions on a planned cadence. The second path is a real-time endpoint for low-latency online inference. The serving modes solve different application needs, but they share the same model lineage and promotion logic. Traceability and monitoring surround both paths. Predictions and operational traces remain connected to the model version that produced them. That provides a clearer foundation for investigating behavior, comparing versions, and understanding what was active at a point in time. My role combined data-science and machine-learning engineering responsibilities. I created the repeatable serving patterns, used MLflow for model registration and promotion, kept inference packaging consistent, and connected both batch jobs and online endpoints to monitoring and version traceability. The result is a production MLOps design with two serving modes and one shared lifecycle. The portfolio does not record model types, batch cadence, endpoint latency, traffic, deployment infrastructure, monitoring thresholds, or business-performance metrics, so I do not invent those details. The verified outcome is the operational capability: approved, versioned models can be promoted to batch or real-time serving, and predictions remain traceable to their model lineage. That is the difference between a successful notebook experiment and a model that can be managed in production.
